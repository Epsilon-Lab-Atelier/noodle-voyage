# Noodle Voyage 2026

日本と世界の麺料理を、地域、麺の種類、味の特徴、そして自分の好みから探せるブラウザアプリです。

これから食べたい一杯と、実際に食べた記録を、自分の端末に残せます。アカウント登録は不要で、記録がサーバーへ送られることはありません。

## できること

### 好みを登録する

- **60秒診断**: 8つの質問に答えるだけで好みを登録できます
- **詳細診断**: 17項目の味覚と、麺の太さ・硬さ・弾力・もちもち感・なめらかさを細かく設定できます
- 診断しなくても、料理を探したり記録したりできます

### 探す

3つの入口から探せます。上部メニューの「探す」から選んでください。

- **一覧から探す**: 名前、地域、麺の種類、位置づけ（ご当地・定番スタイル・現代スタイル・世界の地域料理）、味の特徴で絞り込みます
- **地図から探す**: 都道府県タイル地図と、日本を中心に置いた世界地図から、旅行先の料理を探します
- **味覚マップから探す**: 2つの特徴を軸にして、似た一杯や意外な一杯を見つけます

探し方を切り替えても、絞り込み条件はそのまま引き継がれます。検索条件はURLに保存されるので、そのまま共有できます。

### 特徴から絞り込む

「濃厚」「コシが強い」「汁あり」のように、日本語の特徴を選んで絞り込めます。

- よく使う特徴はボタンで並んでいます。すべての特徴は「すべての特徴を開く」から6つのグループで確認できます
- 「特徴を検索」に入力すると、言い換えでも見つかります。「こってり」で「濃厚」、「硬め」で「コシが強い」など
- **同じグループの中は、どれか一つ**に当てはまれば表示されます
- **グループをまたぐ場合は、すべて**に当てはまる料理だけが表示されます
- 「除外」を選ぶと、その特徴を持つ料理を隠せます
- 選択中の条件は日本語のタグで表示され、押すと外せます

絞り込みは、料理に書かれたタグだけでなく、資料で確認した特徴、麺やスープの構成、味覚値からの推定をまとめた索引を使います。推定による一致は料理カードの特徴としては表示せず、詳細画面で「太麺に近い: 麺の太さ 3.7 / 5」のように根拠つきで説明します。公式にそう分類されているという意味ではありません。

### 味覚マップの見方

横軸と縦軸に好きな特徴を選ぶと、料理が0から5の正方形に配置されます。

- 同じ味覚値の料理は**1つのバブルにまとまり**、バブルの大きさが件数を表します
- バブルを選ぶと、その座標にある料理を一覧で確認できます
- 「分布を見る」と「料理を一件ずつ見る」を切り替えられます
- 「0-5全体に戻す」「結果に合わせる」「選択を解除」で表示範囲を操作できます
- グラフの内容は表でも確認できます

見やすさのために料理の位置をずらすことはありません。表示されている位置が、その料理の実際の味覚値です。

### 比べる

日本と世界を横断して、最大3件まで横並びで比較できます。

### 記録する

4つの役割を分けています。

| | 役割 |
|---|---|
| **食べたい** | これから食べたい料理、お店、メニューを保存します |
| **ごちそうさま** | 実際に食べた1回ごとの記録を保存します |
| **お気に入り** | ごちそうさまの記録から、特に気に入ったものを選びます |
| **自分のお店** | 自分で見つけたお店とそのメニューを保存します |

同じ料理を何度食べても、その都度記録できます。記録には日付、5段階の評価、感想を残せます。

食べた記録からは、訪れた都道府県と地方、麺の種類ごとの件数、定番スタイルと現代スタイルの図鑑、世界の国・地域数が自動で集計されます。

### 自分のお店と一杯

気になるお店を、店名だけで保存できます。住所、Google マップ・食べログ・公式サイトのリンク、営業の状態、メモは後から足せます。お店ごとにメニューを登録し、カタログの料理と結びつけると、その記録も図鑑の集計に入ります。

- 同じ店が二重に登録されそうなときは候補を知らせます。まとめるかどうかは利用者が決めます。自動では統合も削除もしません。
- 保存できるURLは https のみで、Google マップと食べログはそれぞれのドメインだけを受け付けます。
- 全国の店を集めた公開データベースは作りません。点数、口コミ、写真、営業時間、価格の自動取得も行いません。
- 料理詳細から「このスタイルのお店を地図で探す」でGoogle マップの検索を開けます。現在地は、ボタンを押したときだけ、地図を開くためのおおよその位置として使います。保存はしません。

### アプリとして使う

Noodle Voyageをホーム画面に追加すると、いつでもすぐに開けます。ガイドの「アプリとして使う」、モバイルのメニュー、表示設定から追加方法を開けます。

- 対応ブラウザーではインストールできます。ブラウザーが追加を提案できる状態のときだけ「ホーム画面に追加」ボタンを表示します。
- iPhone・iPadではSafariの共有メニューから「ホーム画面に追加」を選びます。手順はアプリ内に表示します。
- すでにホーム画面から起動している場合は、追加の案内を出しません。
- 初回アクセス直後に追加を促すことはありません。何かを保存したあとに一度だけ、控えめにお知らせします。「今はしない」を選ぶと、しばらく再表示しません。この選択は端末内にのみ保存します。

**ホーム画面に追加しても、記録はクラウドへ送信されません。** 記録はこの端末のブラウザー内に保存されます。ブラウザーのサイトデータを削除すると、ホーム画面へ追加した状態でも保存内容が失われる場合があります。定期的にマイ記録からJSONを書き出してください。

新しいバージョンを検出したときは「新しいバージョンがあります」と表示し、更新するかどうかを選べます。入力途中の内容があるときは、更新前に確認します。保存した記録は更新後もそのまま残ります。

### そのほか

- 各料理からGoogle画像検索を開けます
- JSONでバックアップを書き出し、別の端末で読み込めます
- 一度読み込んだ後は、ホーム、料理一覧、条件検索、特徴検索、好み診断、おすすめ、料理詳細、比較、味覚マップ、食べたい、ごちそうさま、お気に入り、自分のお店とメニュー、設定をオフラインで利用できます
- 地図検索、画像検索、外部サイトの閲覧には通信が必要です。オフラインで外部リンクを押すと、その旨を表示します
- 文字サイズ、高コントラスト、動きを減らす設定に対応しています

## 収録データについて

日本のご当地料理と世界の麺料理を収録しています。世界の麺料理を一律に「外国のラーメン」とは扱わず、次の3つの軸で分類しています。

- **地域**: 日本 / 世界
- **麺の種類**: ラーメン / うどん / そば / 焼きそば / 世界の麺料理 / その他
- **位置づけ**: ご当地 / 定番スタイル / 現代スタイル / 世界の地域料理

### 定番スタイルと現代スタイル

醤油ラーメン、かけうどん、もり・ざるそば、ソース焼きそばなど、特定の地域に限らない基本の様式を20件収録しています。ご当地料理から近い定番スタイルへ、定番スタイルから代表的なご当地料理へ、それぞれたどれます。

濃厚魚介豚骨つけ麺、昆布水つけ麺のように、複数の店へ広がった比較的新しい技法は「現代スタイル」として分けています。特定の店の限定メニューは収録しません。

定番スタイルと現代スタイルは地域を割り当てないため、地図と都道府県・地方の集計には含まれません。一覧、検索、好み診断、比較、味覚マップ、スタイル図鑑には含まれます。

料理名と地域は公開資料を参照し、紹介文、タグ、味覚値はアプリ用に独自編集しています。定番スタイルの代表値は一つの決まったレシピではなく、店舗や地域による幅を持つ中心像です。公式評価、人気順位、官能試験の実測値ではありません。

「好みとの一致度」は好みとの近さを示すアプリ内の指標で、料理の品質、人気、好きになる確率を表すものではありません。情報源の充実度によって一致度が下がることはありません。

## 原材料とアレルギーについて

本アプリは料理の一般的な特徴を示すもので、**店舗ごとの原材料、調理環境、アレルギー対応、宗教上の食事対応を保証しません。**

健康や安全に関わる確認は、必ず利用する店舗へ直接お問い合わせください。

## 料理画像について

各料理カードと詳細画面の「Google画像検索」から、料理名と地域を使った画像検索を開けます。

画像検索結果はGoogleおよび各掲載サイトが提供する外部情報です。画像の権利や利用条件は、掲載元で確認してください。

## 端末内データ

食べたい、ごちそうさま、お気に入り、自分のお店とメニュー、好み設定はブラウザのIndexedDBへ保存され、サーバーへ送信されません。写真は取得しません。現在地は、地図検索のボタンを押したときだけ取得し、保存はしません。

以前のバージョンの記録は、初回起動時に自動で新しい形式へ引き継がれます。記録のIDはそのまま保たれ、移行が完了するまで以前のデータは削除されません。

ブラウザのデータを削除すると記録も消えるため、必要に応じて記録画面からJSONを書き出してください。

## 開発

### 必要環境

- Node.js 22.12以降
- npm 10以降

### はじめる

```bash
npm ci
npm run dev
```

開発サーバーの起動前に、CSVから公開用JSONを自動生成します。

### 主なコマンド

```bash
npm run check:data      # データ生成と検証
npm run check:static    # 静的構造の検査
npm run check:privacy   # 個人情報・秘密情報の検査
npm run check:pwa       # ビルド後のManifestとService Workerの検査
npm test                # テスト
npm run build           # 本番ビルド
npm run release:check   # 上記をまとめて実行
```

`npm run data:build`は公開用JSONに加えて、`data/master/design-tokens.json`から`src/styles.tokens.css`を生成します。色、余白、角丸、影、モーションはこのファイルのカスタムプロパティを参照します。スタイルシートへ直接色を書かないでください。

### PWAと公開パス

GitHub Pagesはリポジトリ名のサブパスで公開されるため、Manifestの`id`・`scope`、Service Workerのscope、アイコンURLはすべて`vite.config.ts`の`base`から生成します。リポジトリ名を各ファイルへ直接書かないでください。`npm run check:pwa`がビルド結果を検査します。

Manifestの`id`は`base`と一致させています。`id`を省略した場合にブラウザーが`start_url`から導く識別子と同じ値のため、すでにホーム画面へ追加している利用者のアプリが別アプリとして扱われることはありません。`id`を変更するとインストール済みのアプリが別扱いになります。

#### 実機での確認項目

次はCIでは確認できないため、リリース前に実機で確認します。

- Android Chromeで「ホーム画面に追加」ができる
- iPhone Safariの共有メニューから「ホーム画面に追加」ができる
- ホーム画面から起動したときにアドレスバーが出ない
- ノッチ・Dynamic Island・ホームインジケーターに内容が重ならない

### データ編集

編集の原本は次のファイルです。JSONは直接編集せず、`npm run data:build`で再生成します。

```text
data/master/dishes.csv                     料理の基本情報と分類
data/master/taste-scores.csv               味覚17項目と麺6指標の値
data/master/relations.csv                  定番スタイルと料理の関係
data/master/sources.csv                    情報源（visibility=internalは公開されません）
data/master/regions.json                   都道府県と地方のマスター
data/master/taxonomy.json                  分類の定義と表示名
data/master/feature-tag-taxonomy.ja.json   特徴タグの日本語辞書と絞り込み定義
data/master/release-targets.json           公開件数と関連件数の期待値
data/facets/                               facet索引のseed、導出規則、監査、レビュー待ち一覧
data/standard-styles/                      定番スタイル20件の調査元データと検証結果
data/contemporary-styles/                  現代スタイル2件の調査元データ
data/additions/                            リリースごとの追加データ
```

守るべき規則は次の6点です。

1. 料理IDは公開後に変更しない。`data/master/legacy-dish-ids.json`のIDは利用者の記録が参照するため、常に公開状態を維持する
2. 味覚値を料理名から自動生成せず、CSVへ明示的に記載する
3. 公開資料を確認できない料理は`publication_status=internal_pending`とし、公開データへ含めない
4. 公開する料理の関連IDを未解決のまま残さない。`npm run check:data`が0件であることを検査する
5. 特徴タグは英語IDのまま画面へ出さない。`feature-tag-taxonomy.ja.json`へ日本語表示を登録する。未登録の英語タグがあると`npm run check:data`が失敗する
6. 味覚値・麺指標からの推定は検索にだけ使い、料理の特徴として表示しない。v2.1.2の既定値しか根拠がない麺の数値からは、太麺・細麺などを作らない

表計算ソフトで確認する場合は`npm run data:export-xlsx`を使います。

### 公開前の検査

`npm run check:privacy`は、絶対パス、秘密鍵、トークン形式、公開用でないメールアドレスを検査します。プロジェクト固有の禁止語は、Git管理しない`private-terms.local.txt`へ記載します。

```bash
cp private-terms.example.txt private-terms.local.txt
npm run check:privacy
```

### GitHub Pages

`main`ブランチへpushすると`.github/workflows/deploy-pages.yml`が検査、ビルド、公開を実行します。リポジトリの`Settings > Pages`でSourceを`GitHub Actions`に設定してください。
